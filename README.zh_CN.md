# FoloToy AI Passport Game Boy 模拟器

设备开机直接进入主菜单。每次启动游戏，在 ROM／存档检查通过后、游戏运行前，复现初代单色 Game Boy 的标志下落和两段提示音；暂停后继续游戏不会重播。提示音遵循已保存的音量和静音设置。这是绘制的复现动画，不执行 Nintendo 启动 ROM；不保证 LCD 色彩和扬声器音色完全一致。动画顺序参考：[Pan Docs](https://github.com/gbdev/pandocs/blob/master/src/Power_Up_Sequence.md)。

游戏中长按机身 OK，选择“息屏”并确认：暂停模拟、关闭 LCD/背光与音频输出，保留内存进度。重新按任一机身功能键或手柄上报的按键唤醒，松开后恢复游戏，不将唤醒按键传入游戏。手柄已断开时停留在暂停页等待重连。这是息屏待机，不是深度睡眠；硬件关机键仍控制电源，不能代替软件息屏。

此检出目录将 SUMI Game Boy 核心移植到 AI Passport（ESP32-C3、8 MB Flash、无 PSRAM、ST7789P3 240×320 屏幕）。Bluepad32 和 BTstack 接收 Xbox 1914 和标准低功耗蓝牙键盘输入；键盘实机兼容性尚未验证。应用现有中文位图菜单、Wi-Fi 游戏管理，以及向 ES8311 扬声器输出的四声道 Game Boy APU。用户确认《宝可梦蓝》画面、按键和普通存档恢复，白屏修复后的《数码暴龙》《彩虹战士》正常游玩，以及《星之卡比》明显更流畅。复杂场景仍可能低于原机速度，音乐节奏也可能变化。仓库不附带商业 ROM。

设备的主页、配对、游戏列表、游戏管理、设置、暂停和错误页面使用统一的初代 GB 四阶灰绿色 LCD 风格。单色游戏像素也使用相同的四阶绿色，包括浅绿色背景；彩色游戏保留自身调色板。右上角保留电量，底部保留按键提示。游戏管理网页也使用相同配色和像素边框。

8 MB 分区为：NVS `0x9000`（24 KiB）、PHY `0xf000`（4 KiB）、游戏应用 `0x10000`（3 MiB）、ROM `0x310000`（4 MiB）、SPIFFS 存档 `0x710000`（960 KiB）。没有官方固件、OTA 或恢复分区。安装此分区表会替换旧布局。初始化存档镜像只可在首次安装时写入；再次写入会清除已有存档。[8 MiB 清洁版镜像与安装说明](docs/development/release/gameboy-firmware.zh_CN.md)用于空白设备首次安装；其中没有游戏、存档、设置或手柄密钥，不能用来更新已配置的设备。

可选的[首次安装预装镜像](docs/development/release/gameboy-firmware.zh_CN.md#可选预装游戏)可加入本地 ROM。它们与上传游戏共用可写目录，可在“游戏管理”改名／删除，删除后重启不恢复，空间可用于新上传游戏。本地 1.4 预装版包含用户提供的汉化《口袋妖怪红》和《超级马里奥大陆》；默认清洁版及 CI 镜像仍为空。重新安装完整镜像会覆盖已有游戏、存档、设置和绑定。

游戏管理会拒绝旧列表发出的删除／改名请求，并刷新页面供用户核对后重试。目录写入结果无法确认时，会提示重启设备核对；在成功读取目录之前，阻止继续修改和启动游戏，保留现有存档。

## 构建和准备镜像

当前本地固件包为 `artifacts/releases/FoloToy-GameBoy-1.4-full.bin`（8 MiB），同目录提供 `.bin.sha256` 校验文件，包含已修复的 1.4 应用及两款预装游戏。本次变化和待完成实测见[双语更新日志](docs/CHANGELOG.zh_CN.md)及[验证记录](docs/development/gameboy-validation.zh_CN.md)。生成固件和 ROM 不进入 Git。

在 PowerShell 激活 ESP-IDF 5.5.3，执行 `idf.py --version` 和 `idf.py build`。输出为 `build/bootloader/bootloader.bin`、`build/partition_table/partition-table.bin`、`build/FoloToy-AI-Passport.bin` 和 `build/saves.bin`。`idf.py flash` 不会写入存档镜像。使用自己合法取得、兼容 DMG 的 `.gb` 文件：

```powershell
& python.exe tools/pack_roms.py --output build/roms.bin path/to/game.gb
& python.exe tools/pack_roms.py --verify build/roms.bin
& ./tools/import_roms.ps1 -Port COM5 -Image build/roms.bin
& ./tools/install_first.ps1 -Port COM5 -RomImage build/roms.bin
```

上述两个命令都仅预览。`import_roms.ps1 -Execute` 才会写入 ROM 分区并回读，核对 SHA-256。它会替换该分区中的全部 ROM。脚本从构建并验证过的分区表获取地址和容量。ROM 镜像最多收录 16 个游戏，同时受 4 MiB 容量限制。

**仅首次安装**，在核对设备及数据影响后，`install_first.ps1 -Execute` 写入经校验的合并固件、初始存档镜像和 ROM 容器，并回读核对。这会重置 NVS、ROM 与存档。普通 ROM 更新不应全片擦除。开发板使用原生 USB Serial/JTAG，需选实际串口。之后更新应用应分段烧录，保留存档和 ROM 分区。

## 操作和限制

设置页底部信息栏显示固件版本，调整选项时也保留版本号。本次 BLE 发现修复将版本从 1.3 升为 **1.4**。版本唯一来源是根目录 `CMakeLists.txt` 中的 `PROJECT_VER`，界面读取已编译固件的应用描述信息，与启动日志保持一致。本次编号不等于发布 Release，也不代表手柄／键盘已完成实机验收。

具体型号及传输协议限制见[反馈手柄协议表](docs/development/gameboy-sources.zh_CN.md#反馈手柄的协议)。四款反馈手柄均未使用 1.4 实测；猎户座二代青春版的不同版本采用的蓝牙协议并不相同。

### 蓝牙键盘

每轮扫描最多显示八个候选设备。找不到目标设备时，可退出再进入配对页刷新列表；已经选中设备时，长按 OK 取消也会刷新。正在配对或重连的目标在明确取消前会保留，刷新不会清除绑定。

进入“配对键盘或手柄”，让键盘进入蓝牙配对模式，用机身按键选中名称并按 OK。候选接纳 Keyboard、Gamepad 和 Joystick，不按品牌或名称筛选。没有声明具体类型、但广播 HID 服务（0x1812）的设备也可进入列表；这类设备没有名称时显示 **BLE HID**。选中连接后，必须通过报告描述符确认是键盘、手柄或摇杆才接收输入。广播包与扫描响应中分开的名称、类型和 HID 服务信息按地址及地址类型合并；缓存有数量上限，连续五秒未收到该设备数据后失效，停止扫描时清空。能被发现不代表特定型号已兼容。ESP32-C3 不支持经典蓝牙，也不支持 USB／2.4 GHz 接收器；仅有蓝牙版本号不能证明兼容。一次只使用一个输入设备。

| 键盘按键 | Game Boy 按钮 |
| --- | --- |
| W / A / S / D | 上／左／下／右 |
| J / K | A / B |
| L / I | Start / Select |

映射依据实体按键的 HID 键码，不受大小写影响。原本支持手柄操作的游戏列表、暂停菜单和设置页也可使用 W/S、J/K。模拟器暂停菜单仍由长按机身 OK 打开；L 输入的是游戏的 Start。按状态处理长按、方向与动作组合键以及松开；相反方向相互抵消。独立的媒体键报告不会释放仍按住的字母键，也不映射到游戏操作。当前协议库最多记录十个同时按下的非修饰键，实际还受键盘自身的按键冲突限制。

需要配对码时，屏幕显示六位数字（保留前导零），在键盘输入后按 Enter。长按机身 OK 会取消当前连接并返回选择。绑定密钥沿用现有 NVS 存储；断线会释放全部输入并暂停。当前运行期间，允许扫描时会尝试重连选中的设备；重启后需重新选择键盘以复用绑定，蓝牙地址变化也可能需要重新选择。切换键盘不需要清空 NVS。

键盘功能已实现，但**尚无任何实体键盘测试，包括迈从**。主机测试覆盖映射和有代表性的数组式、带 Report ID、位图式 HID 报告，不代表所有厂商描述符和无线行为均兼容。未声明键盘类型的广播、非标准报告、配对差异、重连、延迟、组合键冲突及新界面布局仍需实机验证。

中文图形化开机菜单左上角显示“GB模拟器”，提供“配对键盘或手柄”“游戏管理”“设置”三个入口，机身上／下键选择，OK 进入。右上角读取电量计；读取失败显示 `?`。底栏提示机身三键操作。设置会把音量（0–100%）、亮度（10–100%）和声音开关保存到 NVS。选中音量或亮度后按 OK 编辑，用上／下键按 10% 调整，再按 OK 保存。设置页的按键说明统一放在底栏，超出宽度时横向滚动；长按 OK 返回进入设置前的页面。

长按 Xbox 1914 配对键直到 Xbox 灯快速闪烁。配对页列出候选手柄；用机身上／下键选择，按 OK 连接；连接过程中长按 OK 可重新选择。方向键和 A/B 对应 Game Boy 按键；View 对应 Select，Menu 对应 Start。游戏运行时，短按机身 OK 也可输入 Start，短按机身上键可输入 Select，供没有 View/Menu 键的小手柄使用；长按机身 OK 仍会暂停。游戏列表用手柄方向键或机身上／下选择，按 A 或机身 OK 启动；底栏还提示长按机身 OK 返回开机菜单。进入游戏时显示简短中文加载页，游戏画面底部提示长按 OK，长按后进入中文图形化暂停页。暂停页用机身或手柄上／下键选择“继续游戏”“同步电池存档”“设置”“息屏”“退出游戏”，按机身 OK 或手柄 A 确认，手柄 B 继续游戏；长按机身 OK 也可退出。设置页也支持手柄上／下、A 确认和 B 返回。设置可直接在暂停时调整，恢复游戏后声音开关与音量立即按新值生效。这里的存档是游戏卡带的电池 RAM，不是任意时刻的画面快照；先在游戏内部保存，下次启动时固件自动载入电池 RAM，再在游戏内选择继续。手柄断线会释放全部输入并暂停。

只有进入“游戏管理”页面时，设备才会开启无密码的 `FoloToy-GB` 热点。页面用四行占满行宽的 16 像素文字显示 Wi-Fi 名称、管理地址、游戏数量和配额及连续空间限制下的可上传空间；长按机身 OK 才退出此页面。手机或电脑无需密码即可连接，然后打开 `http://192.168.4.1`，新版手机网页显示容量使用情况和已安装游戏，可上传 `.gb` 并删除游戏。4 MiB ROM 分区的开头 4 KiB 和末尾 8 KiB 保留给元数据，按 ROM 分块对齐后的游戏合计上限为 4,177,920 字节（3.984375 MiB）；上传还受最大连续空闲空间限制，目录最多收录 16 款。游戏名以 UTF-8 保存，最多 31 字节（约 10 个汉字）。网页从所选文件名自动填入短名称，也可自行编辑；已上传游戏可直接改名，不重写 ROM 或存档。ROM 分区最后 8 KiB 保留两份带 SHA-256 的目录；旧打包目录仍可读取，只有完整写入并提交目录后新游戏才可见。删除游戏会一并删除对应的两份电池存档；若仍安装着字节完全相同的 ROM，则保留共用存档。已失去对应游戏的存档会在启动和进入游戏管理时清理；若 ROM 目录无法可靠读取，则不清理，以免误删。离开页面时 Wi-Fi 射频停止并卸载驱动。附近任何人接入此开放热点后都能访问管理页。请只上传有权使用的 ROM。

有电池的卡带采用两个带格式版本的存档副本，以 ROM SHA-256 标识游戏，并用 CRC-32 校验。文件系统无法挂载时，不会自动格式化，且阻止需要存档的游戏启动。若两个副本均损坏，会阻止启动以免静默覆盖。没有 RTC 的游戏在卡带 RAM 未变化时跳过不必要的存档写入。MBC3 RTC 在设备运行期间推进，关机期间的时间不会补算。Game Boy 的 160×144 画面等比例放大至 240×216，在 240×320 屏幕上居中；通常隔一帧尝试显示一帧，较重场景自适应为每三帧绘制一次，以优先保持模拟器和声音的运行速度。模拟器指令分支启用跳转表；《星之卡比》固定输入的真机核心计时比默认编译方式缩短约 12%–20%，实际游戏速度仍受场景影响。未变化的 20 行区域不传输，显示任务传输画面时模拟器继续运行。APU 直接生成 16 kHz 单声道 PCM，经仅播放的 I2S 通道送入 ES8311，省去声音块重采样；低帧率时 APU 按实际时间额外生成固定时长的声音块，不再拉长单块而改变音高；播放前缓冲四块声音。游戏逻辑未达到稳定原机帧率时，音符切换仍会忽快忽慢；《星之卡比》真机测试已发现这一限制。仅支持 CGB 的卡带仍会被拒绝：32 KiB SRAM 的彩色游戏诊断在音频运行后仅余约 9 KiB 堆，未计入 LCD 传输时模拟速度也只有约 32 帧／秒。GBA 所需内存和 ROM 空间超出本板资源。兼容 CGB 的卡带仍可按 DMG 模式运行。2048 的基本真机检查不能证明其他 ROM 的兼容性或可玩速度。
