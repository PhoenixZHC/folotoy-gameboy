# FoloToy AI Passport Game Boy 模拟器

开机先复现初代单色 Game Boy 的标志下落和两段提示音，再进入主菜单。提示音遵循已保存的音量和静音设置。这是绘制的复现动画，不执行 Nintendo 启动 ROM；不保证 LCD 色彩和扬声器音色完全一致。动画顺序参考：[Pan Docs](https://github.com/gbdev/pandocs/blob/master/src/Power_Up_Sequence.md)。

游戏中长按机身 OK，选择“息屏”并确认：暂停模拟、关闭 LCD/背光与音频输出，保留内存进度。重新按任一机身功能键或手柄上报的按键唤醒，松开后恢复游戏，不将唤醒按键传入游戏。手柄已断开时停留在暂停页等待重连。这是息屏待机，不是深度睡眠；硬件关机键仍控制电源，不能代替软件息屏。

此检出目录将 SUMI Game Boy 核心移植到 AI Passport（ESP32-C3、8 MB Flash、无 PSRAM、ST7789P3 240×320 屏幕）。Bluepad32 和 BTstack 接收 Xbox 1914 的低功耗蓝牙输入。应用现有中文位图菜单、Wi-Fi 游戏管理，以及向 ES8311 扬声器输出的四声道 Game Boy APU。用户确认《宝可梦蓝》画面、按键和普通存档恢复，白屏修复后的《数码暴龙》《彩虹战士》正常游玩，以及《星之卡比》明显更流畅。复杂场景仍可能低于原机速度，音乐节奏也可能变化。仓库不附带商业 ROM。

设备的主页、配对、游戏列表、游戏管理、设置、暂停和错误页面使用统一的初代 GB 四阶灰绿色 LCD 风格；右上角保留电量，底部保留按键提示。游戏管理网页也使用相同配色和像素边框。

8 MB 分区为：NVS `0x9000`（24 KiB）、PHY `0xf000`（4 KiB）、游戏应用 `0x10000`（3 MiB）、ROM `0x310000`（4 MiB）、SPIFFS 存档 `0x710000`（960 KiB）。没有官方固件、OTA 或恢复分区。安装此分区表会替换旧布局。初始化存档镜像只可在首次安装时写入；再次写入会清除已有存档。[8 MiB 清洁版镜像与安装说明](docs/development/release/gameboy-firmware.zh_CN.md)用于空白设备首次安装；其中没有游戏、存档、设置或手柄密钥，不能用来更新已配置的设备。

## 构建和准备镜像

在 PowerShell 激活 ESP-IDF 5.5.3，执行 `idf.py --version` 和 `idf.py build`。输出为 `build/bootloader/bootloader.bin`、`build/partition_table/partition-table.bin`、`build/FoloToy-AI-Passport.bin` 和 `build/saves.bin`。`idf.py flash` 不会写入存档镜像。使用自己合法取得、兼容 DMG 的 `.gb` 文件：

```powershell
& python.exe tools/pack_roms.py --output build/roms.bin path/to/game.gb
& python.exe tools/pack_roms.py --verify build/roms.bin
& ./tools/import_roms.ps1 -Port COM5 -Image build/roms.bin
& ./tools/install_first.ps1 -Port COM5 -RomImage build/roms.bin
```

上述两个命令都仅预览。`import_roms.ps1 -Execute` 才会写入 ROM 分区并回读，核对 SHA-256。它会替换该分区中的全部 ROM。脚本从构建并验证过的分区表获取地址和容量。ROM 镜像最多收录 16 个游戏，同时受 4 MiB 容量限制。

**仅首次安装**，在核对设备及数据影响后，`install_first.ps1 -Execute` 写入经校验的合并固件、初始存档镜像和 ROM 容器，并回读核对。这会重置 NVS、ROM 与存档。普通 ROM 更新不应全片擦除。开发板使用原生 USB Serial/JTAG，需选实际串口。之后更新应用应分段烧录，保留存档和 ROM 分区。

## 操作和限制

中文图形化开机菜单左上角显示“GB模拟器”，提供“配对手柄”“游戏管理”“设置”三个入口，机身上／下键选择，OK 进入。右上角读取电量计；读取失败显示 `?`。底栏提示机身三键操作。设置会把音量（0–100%）、亮度（10–100%）和声音开关保存到 NVS。选中音量或亮度后按 OK 编辑，用上／下键按 10% 调整，再按 OK 保存。设置页的按键说明统一放在底栏，超出宽度时横向滚动；长按 OK 返回进入设置前的页面。

长按 Xbox 1914 配对键直到 Xbox 灯快速闪烁。配对页列出候选手柄；用机身上／下键选择，按 OK 连接；连接过程中长按 OK 可重新选择。方向键和 A/B 对应 Game Boy 按键；View 对应 Select，Menu 对应 Start。游戏列表用手柄方向键或机身上／下选择，按 A 或机身 OK 启动；底栏还提示长按机身 OK 返回开机菜单。进入游戏时显示简短中文加载页，游戏画面底部提示长按 OK，长按后进入中文图形化暂停页。暂停页用机身上／下键选择“继续游戏”“同步电池存档”“设置”“息屏”“退出游戏”，按 OK 确认；长按 OK 也可退出。设置可直接在暂停时调整，恢复游戏后声音开关与音量立即按新值生效。这里的存档是游戏卡带的电池 RAM，不是任意时刻的画面快照；先在游戏内部保存，下次启动时固件自动载入电池 RAM，再在游戏内选择继续。手柄断线会释放全部输入并暂停。

只有进入“游戏管理”页面时，设备才会开启无密码的 `FoloToy-GB` 热点。页面用四行占满行宽的 16 像素文字显示 Wi-Fi 名称、管理地址、游戏数量和配额及连续空间限制下的可上传空间；长按机身 OK 才退出此页面。手机或电脑无需密码即可连接，然后打开 `http://192.168.4.1`，新版手机网页显示容量使用情况和已安装游戏，可上传 `.gb` 并删除游戏。网页上传执行 ROM 合计 3 MiB 配额，还受最大连续空闲空间限制；已有游戏超过配额时会保留，但拒绝继续上传；目录最多收录 16 款。游戏名以 UTF-8 保存，最多 31 字节（约 10 个汉字）。网页从所选文件名自动填入短名称，也可自行编辑；已上传游戏可直接改名，不重写 ROM 或存档。ROM 分区最后 8 KiB 保留两份带 SHA-256 的目录；旧打包目录仍可读取，只有完整写入并提交目录后新游戏才可见。删除游戏会一并删除对应的两份电池存档；若仍安装着字节完全相同的 ROM，则保留共用存档。已失去对应游戏的存档会在启动和进入游戏管理时清理；若 ROM 目录无法可靠读取，则不清理，以免误删。离开页面时 Wi-Fi 射频停止并卸载驱动。附近任何人接入此开放热点后都能访问管理页。请只上传有权使用的 ROM。

有电池的卡带采用两个带格式版本的存档副本，以 ROM SHA-256 标识游戏，并用 CRC-32 校验。文件系统无法挂载时，不会自动格式化，且阻止需要存档的游戏启动。若两个副本均损坏，会阻止启动以免静默覆盖。没有 RTC 的游戏在卡带 RAM 未变化时跳过不必要的存档写入。MBC3 RTC 在设备运行期间推进，关机期间的时间不会补算。Game Boy 的 160×144 画面等比例放大至 240×216，在 240×320 屏幕上居中；通常隔一帧尝试显示一帧，较重场景自适应为每三帧绘制一次，以优先保持模拟器和声音的运行速度。模拟器指令分支启用跳转表；《星之卡比》固定输入的真机核心计时比默认编译方式缩短约 12%–20%，实际游戏速度仍受场景影响。未变化的 20 行区域不传输，显示任务传输画面时模拟器继续运行。APU 直接生成 14 kHz 单声道 PCM，经仅播放的 I2S 通道送入 ES8311，省去声音块重采样；低帧率时 APU 按实际时间额外生成固定时长的声音块，不再拉长单块而改变音高；播放前缓冲四块声音。游戏逻辑未达到稳定原机帧率时，音符切换仍会忽快忽慢；《星之卡比》真机测试已发现这一限制。仅支持 CGB 的卡带仍会被拒绝：32 KiB SRAM 的彩色游戏诊断在音频运行后仅余约 9 KiB 堆，未计入 LCD 传输时模拟速度也只有约 32 帧／秒。GBA 所需内存和 ROM 空间超出本板资源。兼容 CGB 的卡带仍可按 DMG 模式运行。2048 的基本真机检查不能证明其他 ROM 的兼容性或可玩速度。
