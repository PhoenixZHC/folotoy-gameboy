# Game Boy 基准验收

## 回退基准

历史回退包：`artifacts/baselines/20260917-173843-3f40fec9e627/`。应用 2503632 字节，SHA-256 为 `3f40fec9e62789d53e724f01b1598442fc59e0b5ce62e586b216bc96415df98d`。包含源码、依赖、配置、应用和 ELF，不含设备 ROM 与用户数据。本轮验收发现该包存在 IDLE 看门狗告警，不能将它标为已验收稳定版。

随后构建的 2503760 字节应用，在连续超出帧预算时至少每 250 毫秒阻塞一个系统 tick，让低优先级 IDLE 任务有机会运行，没有关闭看门狗。已完成构建、镜像布局校验及 COM14 仅应用烧录，游戏回归仍待完成。证据：`build/stability_acceptance.log`（143438 毫秒处原始告警）、`build/idle_watchdog_fix_validation.log`（复测）。

候选版归档：`artifacts/baselines/20260917-175524-13c5f6667bb4/`，应用 SHA-256 为 `13c5f6667bb4303abfaa6510fceef14f00caac7e0e7d213b3d182b98b1f8eb97`。两个包的文件校验和源码压缩包完整性均通过；候选版尚不是已通过游戏实测的稳定版。

## 开机动画和息屏新增功能

用户验收：用户确认修正后的动画速度、息屏黑屏静音和按键唤醒恢复原游戏进度均正常。串口记录 56971 毫秒息屏、60945 毫秒唤醒，显示和音频恢复均返回 `ESP_OK`。本次功能验收闭环；没有分别枚举所有手柄按键，也未做长时间待机测试。

开机/息屏迭代的应用为 2508736 字节，构建、合并镜像布局验证和 COM14 仅应用烧录通过。19 组定向主机测试通过（`build/host-regression-mkj7s765/results.json`），最终提示音包络测试和中文字形覆盖在对应修改后复测通过。新增测试覆盖标志裁切、最终位置、提示音归零，以及唤醒按键释放门控和时钟回绕；随后用户已确认板上的显示和唤醒行为。

首版全屏绘制使开机动画明显偏慢。改成仅更新变化条带后，`build/boot_sleep_final_validation.log` 记录开机后 5090 毫秒动画结束，首版为 7620 毫秒。首轮串口捕获随后遇到设备/端口错误而中断，不能作为持续运行稳定的证据。复现采用卡带头部标志像素和合成的两段提示音，不使用原始启动 ROM，不声称时序、LCD 响应和扬声器声音完全一致。

电源键控制硬件电源。暂停页新增息屏待机：模拟器暂停、LCD/背光关闭、音频 codec 挂起，蓝牙保持可用。释放旧按键后重新按机身/手柄按键唤醒，等待唤醒按键释放后恢复，不向游戏透传该按键。手柄断开时唤醒仍停留暂停页。实际显示、声音和唤醒体验已获上述用户确认；未测功耗，不属于深度睡眠。

## 四阶配色界面主题

后续 2509072 字节应用将设备的中文菜单、管理信息、暂停设置、状态及游戏底部提示统一为初代 GB 风格的四阶灰绿色 LCD 配色、像素边框和反白选中项。电量、导航位置及底部操作提示保留；内嵌的游戏管理网页也使用同一配色及方形控件。应用构建、合并镜像布局校验、字形覆盖和 COM14 仅应用烧录通过。`build/dmg_theme_validation.log` 记录开机动画在 5086 毫秒结束，采集的启动阶段无 UI 错误。本轮浏览器预览不可用。用户随后确认设备菜单文字清楚、其他页面正常；内嵌网页的新主题尚未单独在浏览器中目视验收。

用户确认菜单文字清楚，但发现游戏画面上方仍是旧浅色背景。根因是 `prepare_game_screen()` 仍用 `0xEF9D` 清屏；后续版本改用共享的 `GB_LCD_LIGHT` 主题色填充游戏画面外侧和开机动画，游戏像素不变。修正版构建、镜像布局校验和 COM14 仅应用烧录通过；用户确认游戏画面上下区域及底部操作提示均正常。

## 游戏管理故障回归

最终启动日志：`build/storage_quota_final_boot.log`，已运行到显示、按键、蓝牙扫描和电池初始化。短时启动检查不验证管理网页事务或游戏中的看门狗行为，本轮没有要求用户重复操作回归。

随后构建的 2503744 字节应用补上上传合计 3 MiB 限制。单次可上传大小为剩余配额和最大连续空闲区域中的较小值；网页 API 容量显示为 3 MiB 配额。若已有游戏超过配额，不会自动删除。游戏列表 JSON 也为转义后的名称预留足够空间。构建、合并镜像校验和 COM14 仅应用烧录通过。

`build/host-regression-zhbgenkc/results.json` 中 17 组通过，随后新增的删除接口测试单独通过，合计 18 组。实际存储代码在 RAM 模拟 Flash 上测试上传中断、长度错误/GBC-only 头部、重名、目录写入中断、删除失败、重试、改名、空间复用、内容损坏及合计配额。模拟器使用确定性的测试摘要，不验证真实 SHA-256。实际 HTTP 删除处理函数配合隔离依赖，测试共用存档、无效编号、跨站拒绝、存档不可用以及写入/清理失败。原有存档文件测试覆盖主机实际文件删除。这些分层测试不能代替设备 HTTP 完整事务或物理断电验证。

## 音频限制

输出仍为 14 kHz，APU 直接生成相同采样率的声音块。音频队列等待次数表示任务等待下一块数据，不能直接当作 I2S 欠载次数；没有队列丢块、音调测试通过，也不能证明音乐绝对连续。用户反馈忽快忽慢仍存在，但改善明显。游戏音符事件仍依赖模拟 CPU 的推进，缓冲无法恢复已经延迟的游戏事件；复杂场景稳定原速音乐不在已验收结果内。
