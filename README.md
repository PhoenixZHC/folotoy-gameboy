# Game Boy for FoloToy AI Passport

Power-on opens the home menu directly. Each game launch recreates the original monochrome Game Boy logo descent and two-note chime after ROM/save checks and before gameplay; resuming a paused game does not replay it. The chime follows saved volume/mute settings. This is a rendered recreation, not execution of Nintendo's boot ROM; exact LCD colour and speaker timbre are not guaranteed. Sequence reference: [Pan Docs](https://github.com/gbdev/pandocs/blob/master/src/Power_Up_Sequence.md).

During play, hold board OK, select **Screen off**, and press OK. Emulation pauses, LCD/backlight and codec output are disabled, and RAM progress is retained. A fresh press of any board function button or a reported controller button wakes the display; release it to resume without forwarding the wake press to the game. If the controller disconnected, the pause page waits for reconnection. This is screen-off standby, not deep sleep. The hardware power button still controls power and cannot replace this software action.

This checkout ports the SUMI Game Boy core to AI Passport (ESP32-C3, 8 MB Flash, no PSRAM, ST7789P3 240×320 display). Bluepad32 and BTstack receive Xbox 1914 and standard Bluetooth LE keyboard input; keyboard hardware compatibility remains unverified. The application has a Chinese bitmap menu, a Wi-Fi game manager, and a four-channel Game Boy APU feeding the ES8311 speaker. The user confirmed Pokemon Blue display/control and ordinary save recovery, normal Digimon/Rainbow Fighter play after the white-screen fix, and noticeably smoother Kirby play. Complex scenes can still run below original speed and vary the music tempo. No commercial ROM is included in the repository.

The device's home, pairing, game list, management, settings, pause and error screens share a four-shade DMG LCD theme. Monochrome game pixels use the same four green shades, including a light green background; color games retain their own palettes. The battery indicator remains at the top right and button guidance remains along the bottom. The management web page follows the same palette and pixel-border treatment.

The 8 MB layout is NVS at `0x9000` (24 KiB), PHY at `0xf000` (4 KiB), one game app at `0x10000` (3 MiB), ROMs at `0x310000` (4 MiB), and SPIFFS saves at `0x710000` (960 KiB). There is no official firmware, OTA, or recovery partition. Installing this table replaces the old layout. The initial saves image must be written only on first installation because writing it again destroys existing saves. The [clean 8 MiB release image and installation guide](docs/development/release/gameboy-firmware.md) cover blank-device installation. The image contains no games, saves, settings, or controller keys; do not use it to update an already configured device.

An optional [preloaded first-install image](docs/development/release/gameboy-firmware.md#optional-preinstalled-games) can include local ROMs. They use the same writable catalog as uploaded games: rename/delete them in Game management, reuse freed space, and keep deletions across restarts. The local 1.4 image includes the user-supplied Chinese Pokemon Red and Super Mario Land; the default clean/CI image remains empty. Reinstalling a full image overwrites existing games, saves, settings and bonds.

Game management rejects delete/rename requests from an outdated list and refreshes the page before the user tries again. If a directory write cannot be confirmed, management asks for a device restart to check the result; further changes and game launches are blocked until the directory is read successfully. Existing saves are retained while the result is uncertain.

## Build and prepare images

The current local package is `artifacts/releases/FoloToy-GameBoy-1.4-full.bin` (8 MiB), with an adjacent `.bin.sha256` checksum. It contains the repaired 1.4 application and both preinstalled games. See the [bilingual changelog](docs/CHANGELOG.md) and [validation record](docs/development/gameboy-validation.md) for this build's results and remaining device checks. Generated firmware and ROMs are excluded from Git.

Activate ESP-IDF 5.5.3 in PowerShell, then run `idf.py --version` and `idf.py build`. The resulting files are `build/bootloader/bootloader.bin`, `build/partition_table/partition-table.bin`, `build/FoloToy-AI-Passport.bin`, and `build/saves.bin`. `idf.py flash` does not write the saves image. Use legally obtained DMG-compatible `.gb` files:

```powershell
& python.exe tools/pack_roms.py --output build/roms.bin path/to/game.gb
& python.exe tools/pack_roms.py --verify build/roms.bin
& ./tools/import_roms.ps1 -Port COM5 -Image build/roms.bin
& ./tools/install_first.ps1 -Port COM5 -RomImage build/roms.bin
```

Both commands above are dry runs. `import_roms.ps1 -Execute` writes only the ROM partition and reads it back for SHA-256 verification. It replaces all ROMs in that partition. The script obtains its address and size from the verified built partition table. The ROM image stores up to 16 games, subject to the 4 MiB capacity.

On a **first installation only**, after reviewing the device and data impact, `install_first.ps1 -Execute` writes the verified merged firmware, initial saves image, and ROM container, then reads them back. It resets NVS, ROMs, and saves. Do not run a full-chip erase as part of an ordinary ROM update. The board uses native USB Serial/JTAG; select the actual serial port. A future application update should use segmented flashing and leave the saves and ROM partitions untouched.

## Controls and boundaries

Settings displays the firmware version in its bottom information row, including while adjusting an option. The current version is **1.4**, incremented from 1.3 for the BLE discovery fixes. The single source is `PROJECT_VER` in the root `CMakeLists.txt`; the screen reads the built application descriptor, keeping it aligned with startup logs. This version assignment does not publish a release or establish controller/keyboard hardware compatibility.

Controller model and transport limits are documented in the [reported-controller protocol table](docs/development/gameboy-sources.md#reported-controller-protocols). The four reported models have not been physically tested with 1.4; the Ultimate 2C name covers different Bluetooth transports.

### Bluetooth keyboards

Each scan lists up to eight candidates. If the desired device is missing, leave and reopen pairing to refresh the list, or cancel the current selection with a long OK press. A selected pairing/reconnection target is retained until explicitly cancelled; refreshing does not erase bonds.

Select **Pair keyboard or controller**, put the keyboard in Bluetooth pairing mode, select its name with the board keys, and press OK. Keyboard, Gamepad and Joystick candidates are accepted without a brand/name filter. Devices without a specific appearance can also appear when they advertise the HID service (0x1812); unnamed candidates of this kind display **BLE HID**. After selection, the report descriptor must identify a keyboard, gamepad or joystick before input is accepted. Names, appearance and HID service information split across advertising and scan-response packets are merged by address and address type. The bounded cache expires after five seconds of inactivity and is cleared when scanning is stopped. Discovery does not establish compatibility with a particular controller. ESP32-C3 does not support Bluetooth Classic or USB/2.4 GHz dongles. A Bluetooth version label alone does not establish compatibility. Only one input device is active at a time.

| Keyboard key | Game Boy control |
| --- | --- |
| W / A / S / D | Up / Left / Down / Right |
| J / K | A / B |
| L / I | Start / Select |

Mappings use physical HID usages, independent of letter case. W/S and J/K also navigate the game list, pause menu and settings where controller input is accepted. Board long-press OK still opens the emulator pause menu; L sends the game's Start button. Held keys, simultaneous direction/action keys and releases are processed as state; opposite directions cancel. Separate media-key reports do not release held letters and are not mapped to game controls. The vendored parser accepts up to ten pressed non-modifier keys, subject to the keyboard's own rollover limit.

If authentication requires a passkey, the screen shows six digits (including leading zeroes): type them on the keyboard and press Enter. Long-press board OK cancels the connection and returns to selection. Pairing keys use the existing NVS bonding store; disconnect releases every input and pauses play. The selected device is retried while scanning is enabled during the current run. After reboot, select the keyboard again to reuse its bond; an address change may also require reselection. Do not reset or erase NVS just to switch keyboards.

Keyboard support is implemented but has **not been tested on a physical keyboard**, including MCHOSE. Host checks cover mapping and representative array/Report-ID/bitmap HID reports, not all vendor descriptors or wireless behavior. Missing keyboard appearance, nonstandard HID reports, pairing quirks, reconnect, timing, rollover and the new screen layout require device checks.

The Chinese graphical startup menu is headed **GB emulator** and offers **Pair keyboard or controller**, **Game management**, and **Settings**. Board Up/Down selects and board OK enters. The top-right icon reads the battery gauge; an unavailable reading is shown as `?`. The bottom bar explains the three board keys. Settings persist volume (0–100%), brightness (10–100%), and the sound switch in NVS. Select volume or brightness, press OK to edit, use Up/Down in 10% steps, and press OK to save. All settings key instructions are in a scrolling bottom bar when they exceed its width. Long-press OK returns to the screen that opened Settings.

Hold the Xbox 1914 pairing button until its light flashes quickly. The pairing screen lists nearby candidates; use board Up/Down and OK to connect. While connecting, long-press board OK to choose again. D-pad and A/B map to the Game Boy controls; View maps to Select and Menu maps to Start. During gameplay, a short press of board OK also sends Start, and a short press of board Up sends Select, so controllers without View/Menu can enter game title screens; long-press board OK still pauses. In the ROM list, use D-pad or board Up/Down and press A or board OK to launch; its bottom bar also shows the long-press OK shortcut back to the startup menu. A short Chinese loading page replaces the old English text screen. The game image has a bottom hint for long-press OK; that action opens a Chinese graphical pause page. Board or controller Up/Down selects Resume, Sync battery save, Settings, Screen off, or Exit; board OK or controller A confirms, controller B resumes, and a long board OK press exits. Settings also accepts controller Up/Down, A to confirm, and B to return. Changes to sound and volume on the pause screen take effect when play resumes. The save is cartridge battery RAM, not a snapshot of the screen at an arbitrary moment. Save inside the game first; firmware loads that RAM on the next launch, then use the game's own Continue option. Disconnecting the controller releases all inputs and pauses play.

Game management starts the open `FoloToy-GB` Wi-Fi hotspot only while its screen is active. Four full-width, 16-pixel text rows show the Wi-Fi name, management address, game count, and available upload space after quota and contiguous-space limits. Long-press board OK to leave this screen. Connect a phone or computer without a password and open `http://192.168.4.1`. The mobile web page shows storage usage and the installed-game list, uploads `.gb` files, and deletes games. The 4 MiB ROM partition reserves its first 4 KiB and final 8 KiB for metadata; the bank-aligned aggregate upload limit is 4,177,920 bytes (3.984375 MiB), also subject to the largest contiguous free region. At most 16 games are indexed. Game names are stored as UTF-8 with a 31-byte limit (about 10 Chinese characters). The page fills a short name from the selected filename and lets users edit it or rename existing games without rewriting the ROM or save. Two SHA-256-protected directory copies occupy the final 8 KiB of the ROM partition. The old packed directory remains readable, and uploads become visible only after the entire ROM is written and the new directory is committed. Deleting a game also deletes both battery-save copies, except when an identical ROM remains installed and shares the save. Orphan saves are pruned at startup and when entering game management; cleanup is skipped if the ROM catalog is not trusted. The Wi-Fi radio is stopped and deinitialized when leaving this screen. Anyone nearby who joins the open hotspot can access the management page. Only upload ROMs you may legally use.

Battery-backed saves use two versioned copies with ROM SHA-256 identity and CRC-32. Mount failure blocks battery games without formatting the partition. If both copies are damaged, the game is blocked so they are not silently overwritten. Unchanged cartridge RAM skips unnecessary save writes for games without RTC. The MBC3 RTC advances while the device is running; time during power-off is not reconstructed. Game Boy's 160×144 image is scaled uniformly to 240×216 and centered on the 240×320 display. Normally every other emulated frame is eligible for display; heavy scenes adapt to every third frame to preserve simulation and audio speed. Enabling jump tables for the emulator's opcode dispatch shortened measured Kirby core time by about 12%–20% under fixed on-device input, though speed still depends on the scene. Unchanged 20-row regions are skipped, and a display task transfers the frame while emulation continues. The APU generates 16 kHz mono PCM directly for the playback-only ES8311 I2S path, avoiding block resampling. At low emulation rates, the APU generates extra fixed-duration blocks against wall time rather than stretching one block and changing pitch. Playback starts after a four-block buffer. When game logic does not sustain the original frame rate, note changes can still vary in tempo; the Kirby device check found this limitation. CGB-only cartridges remain rejected: a 32 KiB SRAM color-game probe left only 9 KiB free with audio and ran about 32 emulated frames/s before LCD transfer. GBA is beyond this board's internal RAM and ROM partition budget. CGB-compatible cartridges can still run in DMG mode. The basic 2048 device check does not establish compatibility or playable speed for other ROMs.
